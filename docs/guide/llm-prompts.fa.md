# استفاده از TOON با LLMها

TOON برای انتقال داده‌های ساختاریافته به مدل‌های زبانی بزرگ با هزینه توکن کمتر و اطمینان بیشتر طراحی شده. این راهنما نشان می‌دهد چگونه TOON را در پرامپت‌ها به‌صورت موثر استفاده کنید، هم برای ورودی (ارسال داده به مدل‌ها) و هم برای خروجی (دریافت TOON تولیدی از مدل‌ها).

## چرا TOON برای LLMها

علاوه بر صرفه‌جویی توکن (به [بنچمارک‌ها](/guide/benchmarks) مراجعه کنید)، TOON نگه‌داری‌های ساختاری اضافه می‌کند: طول‌های صریح `[N]` و سرایندهای `{fields}` ردیابی ردیف‌ها را برای مدل‌ها آسان‌تر و اعتبارسنجی خروجی را برای شما ساده‌تر می‌کند. حالت سخت‌گیرانه (strict mode) به تشخیص کوتاه‌سازی و TOON نادرست هنگام رمزگشایی پاسخ‌های مدل کمک می‌کند.

## ارسال TOON به عنوان ورودی

TOON وقتی بهترین نتیجه می‌دهد که قالب را نشان دهید، نه اینکه توصیف کنید. ساختار خودمستند است – مدل‌ها آن را به‌صورت طبیعی تجزیه می‌کنند وقتی الگو را ببینند.

داده‌های کدگذاری‌شده خود را در یک بلوک کد محصور شده قرار دهید (برای وضوح به ` ```toon` برچسب بزنید):

````md
داده‌ها در قالب TOON هستند (تورفتگی ۲ فاصله، آرایه‌ها طول و فیلدها را نشان می‌دهند).

```toon
users[3]{id,name,role,lastLogin}:
  1,Ada,admin,"2025-01-15T10:30:00Z"
  2,Bob,user,"2025-01-14T15:22:00Z"
  3,Cleo,user,"2025-01-13T09:45:00Z"
```

وظیفه: نقش‌های کاربری و آخرین فعالیت آن‌ها را خلاصه کنید.
````

تورفتگی و سرایندها معمولاً کفایت می‌کنند – مدل‌ها TOON را مانند YAML یا CSV آشنا می‌شناسند. طول‌های آرایه صریح (`[N]`) و لیست فیلدها (`{fields}`) به مدل کمک می‌کنند ساختار را ردیابی کند، به‌ویژه برای جداول بزرگ.

> [!NOTE]
> اکثر مدل‌ها هایلایت نحو داخلی TOON ندارند، پس ` ```toon` یا ` ```yaml` هر دو کار می‌کنند. ساختار مهم است.

### داده‌های تودرتو و کلیددار

اشیای تودرتوی یکنواخت قالب جدولی را نمی‌شکنند: یک ستون شیء تودرتو در سرایند به عنوان یک [گروه فیلد تودرتو](/guide/format-overview#nested-field-groups) جمع می‌شود، و ردیف‌ها تخت می‌مانند:

```toon
orders[2]{id,customer{name,country},total}:
  1,Ada,DK,99
  2,Bob,UK,149
```

نقشه‌های اشیای یکنواخت – فلگ‌های ویژگی، کاربران با شناسه، پیکربندی بر محیط – در [قالب جدولی کلیددار](/guide/format-overview#keyed-tabular-objects) جمع می‌شوند، جایی که هر ردیف ورودی کلید خود را حمل می‌کند:

```toon
environments[2:]{region,replicas,debug}:
  production: eu-central-1,6,false
  staging: eu-central-1,2,true
```

قوانین پرامپت‌نویسی همانند است: یک مثال کفایت می‌کند، سرایند به مدل می‌گوید ردیف‌ها را چگونه بخواند.

### حاشیه‌نویسی داده‌ها با کامنت‌ها

رمزگشاها خطوط کامل `#` [کامنت](/guide/format-overview#comments) را قبل از تجزیه حذف می‌کنند، بنابراین می‌توانید داده‌های پرامپتی را به‌دست حاشیه‌نویسی کنید – و خروجی مدل که شامل خطوط توضیحی `#` است همچنان تمیز رمزگشایی می‌شود. رمزگذارها هرگز کامنت تولید نمی‌کنند، پس رفت‌وبرگشت‌ها قانونمند باقی می‌مانند.

```toon
# فقط کاربران فعال، صادرات 2025-01-15
users[2]{id,name,role}:
  1,Ada,admin
  2,Bob,user
```

## تولید TOON از LLMها

برای خروجی، صریح‌تر باشید. وقتی می‌خواهید مدل **تولید** کند TOON:

- **سرایند مورد انتظار را نشان دهید** (مثال: `users[N]{id,name,role}:`). مدل ردیف‌ها را پر می‌کند به‌جای تکرار کلیدها، خطاهای تولید را کاهش می‌دهد.
- **قوانین را بیان کنید**: تورفتگی ۲ فاصله، بدون فاصله پیانی، `[N]` با تعداد ردیف هم‌راستا باشد.

اینجا یک پرامپت هست که هم برای خواندن و هم برای تولید کار می‌کند:

````md
داده‌ها در قالب TOON هستند (تورفتگی ۲ فاصله، آرایه‌ها طول و فیلدها را نشان می‌دهند).

```toon
users[3]{id,name,role,lastLogin}:
  1,Ada,admin,"2025-01-15T10:30:00Z"
  2,Bob,user,"2025-01-14T15:22:00Z"
  3,Cleo,user,"2025-01-13T09:45:00Z"
```

وظیفه: فقط کاربران با نقش "user" را به‌عنوان TOON برگردانید. از همان قالب سرایند استفاده کنید. [N] را به تعداد ردیف‌ها برسانید. فقط بلوک کد را خروجی دهید.
````

**خروجی مورد انتظار:**

```toon
users[2]{id,name,role,lastLogin}:
  2,Bob,user,"2025-01-14T15:22:00Z"
  3,Cleo,user,"2025-01-13T09:45:00Z"
```

مدل `[N]` را به `۲` تنظیم و دو ردیف تولید می‌کند.

### اعتبارسنجی با حالت سخت‌گیرانه

هنگام رمزگشایی TOON تولیدی مدل، از حالت سخت‌گیرانه (پیش‌فرض) برای گرفتن خطاها استفاده کنید:

```ts
import { decode } from '@toon-format/toon'

try {
  const data = decode(modelOutput, { strict: true })
  // موفق – داده معتبر است
}
catch (error) {
  // خروجی مدل نادرست بود (عدم تطابق تعداد، گریز نامعتبر، و غیره)
  console.error('اعتبارسنجی ناموفق:', error.message)
}
```

حالت سخت‌گیرانه تعدادها، تورفتگی، و گریزها را بررسی می‌کند تا بتوانید کوتاه‌سازی یا TOON نادرست را تشخیص دهید. برای جزئیات کامل، به [مرجع API](/reference/api#decode-input-options) مراجعه کنید.

## انتخاب جداکننده برای کارایی توکن

از `delimiter: '\t'` برای جداول جدا شده با تب استفاده کنید اگر توکن حتی کم‌تر می‌خواهید. تب‌ها کاراکترهای واحدی‌اند، اغلب کارآمدتر از کاما توکن‌بندی می‌شوند، و به ندرت در متن طبیعی ظاهر می‌شوند (کاهش گریز نقل‌قول).

```ts
const toon = encode(data, { delimiter: '\t' })
```

وقتی از تب استفاده می‌کنید، به مدل بگویید "فیلدها با تب جدا شده‌اند". برای جزئیات بیشتر درباره جداکننده‌ها، به [نمای کلی قالب](/guide/format-overview#delimiter-options) مراجعه کنید.

## جریانی‌سازی خروجی‌های بزرگ

هنگام کار با مجموعه‌داده‌های بزرگ (هزاران رکورد یا ساختارهای عمیقاً تودرتو)، از `encodeLines()` برای جریان خروجی TOON خط‌به‌خط به‌جای ساخت کل رشته در حافظه استفاده کنید.

```ts
import { encodeLines } from '@toon-format/toon'

const largeData = await fetchThousandsOfRecords()

// جریان مجموعه‌داده بزرگ بدون بارگذاری کل رشته در حافظه
for (const line of encodeLines(largeData, { delimiter: '\t' })) {
  process.stdout.write(`${line}\n`)
}
```

CLI نیز برای تبدیل حافظه‌کارآمد JSON-به-TOON از جریانی‌سازی پشتیبانی می‌کند:

```bash
toon large-dataset.json -o output.toon
```

این رویکرد جریانی از خطاهای خارج‌از-حافظه هنگام آماده‌سازی پنجره‌های متن بزرگ برای LLMها پیشگیری می‌کند. برای جزئیات کامل `encodeLines()`، به [مرجع API](/reference/api#encodelines-input-options) مراجعه کنید.

**مصرف خروجی‌های جریانی LLM:** اگر کلاینت LLM شما متن جریانی عرضه می‌کند و شما بر اساس خط بافر می‌کنید، می‌توانید TOON را به‌صورت افزایشی رمزگشایی کنید:

```ts
import { decodeFromLines } from '@toon-format/toon'

// بافر کردن پاسخ جریانی به خطوط
const lines: string[] = []
let buffer = ''

for await (const chunk of modelStream) {
  buffer += chunk
  let index: number

  while ((index = buffer.indexOf('\n')) !== -1) {
    lines.push(buffer.slice(0, index))
    buffer = buffer.slice(index + 1)
  }
}

// رمزگشایی خطوط بافرشده
const data = decodeFromLines(lines)
```

برای APIهای رمزگشای جریانی، به [`decodeFromLines()`](/reference/api#decodefromlines-lines-options) و [`decodeStream()`](/reference/api#decodestream-source-options) مراجعه کنید.

## نکات و دام‌ها

**نشان دهید، توصیف نکنید.** نحو TOON را به تفکیک توضیح ندهید – فقط یک مثال نشان دهید. مدل‌ها الگو را از متن می‌آموزند. یک بلوک کد ساده با ۲–۵ ردیف موثرتر از پاراگراف‌های توضیح است.

**مثال‌ها را کوچک نگه دارید.** در مثال‌های خود از ۲–۵ ردیف استفاده کنید، نه صدها. مدل از الگو تعمیم می‌یابد. مثال‌های بزرگ توکن هدر می‌دهند بدون بهبود دقت.

**همیشه خروجی را اعتبارسنجی کنید.** TOON تولیدی را با `strict: true` (پیش‌فرض) رمزگشایی کنید تا زود خطاها را بگیرید. بدون بررسی فرض نکنید که خروجی مدل TOON معتبر است.

## مثال واقعی

اینجا یک گردش کار کامل: داده را به مدل بفرستید و پاسخ TOON آن را اعتبارسنجی کنید.

**پرامپت با ورودی TOON:**

````md
لاگ‌های سیستم در قالب TOON (با جداکننده تب):

```toon
events[4	]{id	level	message	timestamp}:
  1	error	Connection timeout	"2025-01-15T10:00:00Z"
  2	warn	Slow query	"2025-01-15T10:05:00Z"
  3	info	User login	"2025-01-15T10:10:00Z"
  4	error	Database error	"2025-01-15T10:15:00Z"
```

وظیفه: فقط رویدادهای سطح error را به‌عنوان TOON برگردانید. از همان قالب استفاده کنید.
````

**اعتبارسنجی پاسخ:**

```ts
import { decode } from '@toon-format/toon'

const modelResponse = `
events[2	]{id	level	message	timestamp}:
  1	error	Connection timeout	"2025-01-15T10:00:00Z"
  4	error	Database error	"2025-01-15T10:15:00Z"
`

const filtered = decode(modelResponse, { strict: true })
// ✓ اعتبارسنجی شد – مدل به‌درستی فیلتر کرد و [N] را به ۲ تنظیم کرد
```
