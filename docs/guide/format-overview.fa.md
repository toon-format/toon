# نمای کلی قالب

مرجع نحو TOON با مثال‌های конкреت. برای مقدمه به [شروع کار](/guide/getting-started) مراجعه کنید.

## چهار قالب

یک **قالب (form)** یک نمایش برای یک مقدار است. کدام قالب به دست می‌آید از شکل داده و جایگاه آن پیروی می‌کند – شما به‌دست انتخاب نمی‌کنید. هر آنچه در ادامه می‌آید نوعی از این چهار قالب است:

| قالب | लागू می‌شود به | شبیه به |
| ---- | ---------- | ---------- |
| [درون‌خطی](#primitive-arrays-inline-form) | آرایه‌های مقادیر ساده | `tags[3]: admin,ops,dev` |
| [فهرستی](#mixed-and-non-uniform-arrays-list-form) | آرایه‌هایی که نه درون‌خطی و نه جدولی می‌گنجند | `items[2]:` سپس `- ` برای هر عنصر |
| [جدولی](#arrays-of-objects-tabular-form) | آرایه‌های اشیای یکنواخت | `items[2]{sku,qty}:` سپس یک ردیف به ازای هر عنصر |
| [جدولی کلیددار](#keyed-tabular-objects) | اشیایی که مقادیرشان اشیای یکنواختند | `users[2:]{age,city}:` سپس یک ردیف ورودی به ازای هر ورودی |

«قالب» به‌صورت عمدی انتخاب شده: این شکل‌ها *درون* TOON هستند، نه قالب‌های هم‌سایه برای JSON یا YAML.

## مدل داده

TOON داده را همانند JSON مدل‌سازی می‌کند:

- **مقادیر ساده (Primitives)**: رشته‌ها، اعداد، بولی‌ها، و `null`
- **اشیاء (Objects)**: نگاشت از کلیدهای رشته‌ای به مقادیر
- **آرایه‌ها (Arrays)**: دنباله‌های مرتب از مقادیر

### قالب‌های ریشه (Root Forms)

یک سند TOON می‌تواند قالب‌های ریشه مختلفی را نمایش دهد:

- **شیء ریشه** (معمول‌ترین): فیلدها در عمق ۰ بدون کلید والد ظاهر می‌شوند
- **آرایه ریشه**: با `[N]:` یا `[N]{fields}:` در عمق ۰ آغاز می‌شود
- **مقدار ساده ریشه**: یک مقدار ساده واحد (رشته، عدد، بولی، یا null)

اکثر مثال‌ها در این اسناد از شیء ریشه استفاده می‌کنند، اما قالب هر سه فرم را به‌طور مساوی پشتیبانی می‌کند ([مشخصات §5](https://github.com/toon-format/spec/blob/main/SPEC.md#5-concrete-syntax-and-root-form))。

## اشیاء

### اشیاء ساده

اشیاء با مقادیر ساده از دستور `key: value` استفاده می‌کنند، با یک فیلد در هر خط:

```toon
id: 123
name: Ada
active: true
```

تورفتگی به‌جای آکولاد می‌آید. یک فاصله بعد از دونقطه می‌آید.

### اشیاء تودرتو

اشیاء تودرتو یک سطح تورفتگی اضافه می‌کنند (پیش‌فرض: ۲ فاصله):

```toon
user:
  id: 123
  name: Ada
```

وقتی یک کلید با `:` تمام می‌شود و در همان خط مقداری ندارد، یک شیء تودرتو باز می‌کند. تمام خطوط در سطح تورفتگی بعدی متعلق به آن شیء هستند.

### اشیاء خالی

یک شیء خالی در ریشه سند خالی تولید می‌کند (بدون خط). یک شیء تودرتو خالی فقط `key:` است، بدون فرزند.

### اشیاء جدولی کلیددار

وقتی یک شیء حداقل دو ورودی دارد که مقادیرشان اشیای یکنواختند (کلیدهای یکسان، مقادیر ساده یا تودرتو-یکنواخت)، به یک قالب جدولی کلیددار جمع می‌شود: ساختار فیلد مشترک یک بار در سرایند ظاهر می‌شود، و هر ورودی یک ردیف می‌شود که کلید خود را حمل می‌کند:

```toon
users[2:]{age,city}:
  alice: 30,Berlin
  bob: 25,Oslo
```

دونقطه بلافاصله بعد از طول (`[2:]`) سرایند کلیددار را علامت‌گذاری می‌کند، و `[N]` تعداد ورودی‌ها را اعلام می‌کند. هر ردیف ورودی `entrykey: cell,cell,…` است – کلید ورودی و به دنبال آن مقادیر برگِ مقدار ورودی به ترتیب فیلدها.

وقتی خود شیء ریشه واجد شرایط است، کلید حذف می‌شود:

```text
[2:]{age,city}:
  alice: 30,Berlin
  bob: 25,Oslo
```

اشیایی که واجد شرایط نباشند، قالب تودرتو را بدون تغییر حفظ می‌کنند: اشیاء تک‌ورودی، اشیایی که مقادیرشان اشکال مختلط یا شامل مقادیر ساده، آرایه‌ها، یا اشیاء خالی باشند. در عمل این باعث می‌شود اکثر نقشه‌های سبک پیکربندی همان‌طور که هستند باقی بمانند ([مشخصات §9.5](https://github.com/toon-format/spec/blob/main/SPEC.md#95-objects-of-uniform-objects--keyed-tabular-form))।

## آرایه‌ها

TOON ساختار آرایه را تشخیص می‌دهد و کارآمدترین نمایش را انتخاب می‌کند. آرایه‌ها همیشه طول خود را در کروشه اعلام می‌کنند: `[N]`.

### آرایه‌های ساده (قالب درون‌خطی)

آرایه‌های مقادیر ساده (رشته، عدد، بولی، null) به‌صورت درون‌خطی نمایش داده می‌شوند:

```toon
tags[3]: admin,ops,dev
```

جداکننده (به‌صورت پیش‌فرض کاما) مقادیر را جدا می‌کند. رشته‌هایی که جداکننده فعال را chứa می‌کنند باید نقل‌قول شوند.

### آرایه‌های اشیاء (قالب جدولی)

وقتی تمام اشیاء در یک آرایه مجموعه کلیدهای یکسانی با مقادیر ساده دارند، TOON از قالب جدولی استفاده می‌کند:

::: code-group

```toon [جدولی پایه]
items[2]{sku,qty,price}:
  A1,2,9.99
  B2,1,14.5
```

```toon [فاصله و نقل‌قول]
users[2]{id,name,role}:
  1,Ada Lovelace,admin
  2,"Smith, Bob",user
```

:::

سرایند `items[2]{sku,qty,price}:` اعلام می‌کند:
- **طول آرایه**: `[2]` یعنی ۲ ردیف
- **نام فیلدها**: `{sku,qty,price}` ستون‌ها را تعریف می‌کند
- **جداکننده فعال**: کاما (پیش‌فرض)

هر ردیف مقادیر را در همان ترتیبی که در لیست فیلدها است، دارد. مقادیر به‌عنوان مقادیر ساده (رشته، عدد، بولی، null) کدگذاری شده و توسط جداکننده جدا می‌شوند.

> [!NOTE]
> قالب جدولی نیازمند مجموعه فیلدهای یکسان در تمام اشیاء است (کلیدهای یکسان، ترتیب در هر شیء می‌تواند متفاوت باشد)، حداقل یک کلید در هر شیء، و هر ستون باید یا ساده‌ارزش باشد یا یک شیء تودرتوی یکنواخت (بخش زیر را ببینید) – آرایه‌هایی که عنصر `{}` خالی داشته باشند یا در یک ستون اشکال مقدار مختلط باشند، به قالب فهرستی برمی‌گردند.

### گروه‌های فیلد تودرتو

یک ستون که مقادیرش اشیاء زیربنای یکنواختند (کلیدهای یکسان در هر عنصر، به‌صورت بازگشتی ساده یا تودرتو-یکنواخت) در سرایند به عنوان یک گروه فیلد تودرتو جمع می‌شود، در حالی که ردیف‌ها تخت می‌مانند:

```toon
orders[2]{id,customer{name,country},total}:
  1,Ada,DK,99
  2,Bob,UK,149
```

سرایند `customer{name,country}` یک ستون شیء تودرتو را اعلام می‌کند؛ سلول‌های هر ردیف از یک گشت colonos-depth-first از لیست فیلدها پیروی می‌کنند، بنابراین `Ada,DK` پر می‌کند `customer.name` و `customer.country` برای اولین سفارش. عمق تودرتو غیرمحدود است ([مشخصات §9.3](https://github.com/toon-format/spec/blob/main/SPEC.md#93-arrays-of-objects--tabular-form))。

### آرایه‌های مختلط و ناهمگون (قالب فهرستی)

آرایه‌هایی که نیازهای جدولی را برآورده نکنند، از قالب فهرستی با نشانگرهای خط تیره استفاده می‌کنند:

```toon
items[3]:
  - 1
  - a: 1
  - text
```

هر عنصر با `- ` در یک سطح تورفتگی عمیق‌تر از سرایند آرایه والد آغاز می‌شود.

### اشیاء به عنوان آیتم‌های فهرست

وقتی یک عنصر آرایه یک شیء است، به‌عنوان یک آیتم فهرست ظاهر می‌شود:

```toon
items[2]:
  - id: 1
    name: First
  - id: 2
    name: Second
    extra: true
```

وقتی یک آرایه جدولی اولین فیلد یک شیء آیتم‌فهرست است، سرایند جدولی در خط خط‌تیره ظاهر می‌شود، با ردیف‌ها دو سطح عمیق‌تر تورفتگی و سایر فیلدها یک سطح عمیق‌تر:

```toon
items[1]:
  - users[2]{id,name}:
      1,Ada
      2,Bob
    status: active
```

وقتی شیء تنها یک فیلد جدولی دارد، همان الگو اعمال می‌شود:

```toon
items[1]:
  - users[2]{id,name}:
      1,Ada
      2,Bob
```

این کدگذاری قانونمند برای اشیاء آیتم‌فهرست است که اولین فیلدشان یک آرایه جدولی است.

### آرایه‌های آرایه‌ها (قالب فهرستی)

وقتی آرایه‌هایی داریم که آرایه‌های ساده درونی دارند:

```toon
pairs[2]:
  - [2]: 1,2
  - [2]: 3,4
```

هر آرایه درونی سرایند خود را در خط آیتم‌فهرست دارد.

وقتی آرایه‌های درونی خود آرایه‌های اشیاء یا آرایه‌های ناهمگون باشند، همان سرایند `- [N]:` در خط خط‌تیره ظاهر می‌شود و آیتم‌های تودرتو یک سطح عمیق‌تر ادامه می‌یابند:

```toon
items[3]:
  - summary
  - id: 1
    name: Ada
  - [2]:
    - id: 2
    - status: draft
```

### آرایه‌های خالی

آرایه‌های خالی به‌عنوان `key: []` برای فیلدها و `[]` در ریشه نمایش داده می‌شوند:

```toon
items: []
```

قالب قدیمی `items[0]:` همچنان برای سازگاری با عقب رمزگشایی می‌شود.

## سرایندهای آرایه

### دستور سرایند

سرایندهای آرایه این الگو را دنبال می‌کنند:

```
key[N<delimiter?>]<{fields}>:
```

جایی که:
- **N** طول عدد صحیح غیرمنفی است
- **delimiter** (اختیاری) جداکننده فعال را صریحاً اعلام می‌کند:
  - غیبالصوت → کاما (`,`)
  - `\t` (کاراکتر تب) → جداکننده تب
  - `|` → جداکننده پایپ
- **fields** (اختیاری) برای آرایه‌های جدولی: `{field1,field2,field3}`

> [!NOTE]
> طول آرایه `[N]` به LLMها کمک می‌کند ساختار را اعتبارسنجی کنند. اگر از مدلی می‌خواهید خروجی TOON تولید کند، طول‌های صریح به شما اجازه می‌دهند کوتاه‌سازی یا داده نادرست را تشخیص دهید.

### گزینه‌های جداکننده

TOON سه جداکننده را پشتیبانی می‌کند: کاما (پیش‌فرض)، تب، و پایپ. جداکننده به محدوده آرایه‌ای که آن را اعلام می‌کند محدود می‌شود.

::: code-group

```toon [کاما (پیش‌فرض)]
items[2]{sku,name,qty,price}:
  A1,Widget,2,9.99
  B2,Gadget,1,14.5
```

```toon [تب]
items[2	]{sku	name	qty	price}:
  A1	Widget	2	9.99
  B2	Gadget	1	14.5
```

```toon [پایپ]
items[2|]{sku|name|qty|price}:
  A1|Widget|2|9.99
  B2|Gadget|1|14.5
```

:::

جداکننده‌های تب و پایپ به‌صورت صریح در کروشه‌های سرایند و آکولادهای فیلد کدگذاری می‌شوند. درون محدوده یک آرایه، فقط جداکننده فعال باعث نقل‌قول می‌شود – سایرین داده‌های عادی هستند. مقادیر فیلدهای شیء (`key: value`) بدون توجه به جداکننده فعال آرایه محیط، از جداکننده سند (§11.1) پیروی می‌کنند.

> [!TIP]
> جداکننده‌های تب اغلب کارآمدتر از کاما توکن‌بندی می‌شوند، به‌ویژه برای داده‌هایی با رشته‌های نقل‌قول‌شده کم. از `encode(data, { delimiter: '\t' })` برای صرفه‌جویی بیشتر در توکن استفاده کنید.

## کامنت‌ها

رمزگشاها هر خطی را که اولین کاراکتر غیرفاصله‌اش `#` باشد، در یک پیش‌گذر واژگانی، قبل از هر چیز دیگری، حذف می‌کنند:

```toon
# پیکربندی سرور
host: example.com
port: 8080
```

کامت‌ها فقط تمام‌خطی هستند – یک `#` در هر جای دیگر خط محتوای عادی است – و فقط سمت رمزگشا هستند: رمزگذارها هرگز آن‌ها را تولید نمی‌کنند، و مقادیر رشته‌ای که با `#` آغاز می‌شوند همیشه نقل‌قول می‌شوند بنابراین خروجی رمزگذار هرگز خطی ندارد که به‌عنوان کامنت خوانده شود. یک کامنت میان ردیف‌های جدولی یا ردیف‌های ورودی، آن‌ها را تمام نمی‌کند ([مشخصات §5.1](https://github.com/toon-format/spec/blob/main/SPEC.md#51-comment-lines))।

## نقل‌قول و انواع

### چه زمانی رشته‌ها نیاز به نقل‌قول دارند

TOON رشته‌ها را **فقط وقتی لازم است** نقل‌قول می‌کند تا کارایی توکن بهینه شود. یک رشته باید نقل‌قول شود اگر:

- خالی باشد (`""`)
- فضای پیشینی یا پیانی داشته باشد
- برابر `true`، `false`، یا `null` باشد (حساس به بزرگی/کوچکی حروف)
- شبیه عدد باشد (مثال: `"42"`، `"-3.14"`، `"1e-6"`، `"05"`، `"+1"`)
- کاراکترهای خاص داشته باشد: دونقطه (`:`)، نقل‌قول (`"`)، بک‌اسلش (`\`)، کروشه، آکولاد، یا هر کاراکتر کنترلی در U+0000–U+001F
- جداکننده مربوطه را داشته باشد (جداکننده فعال در محدوده آرایه، یا جداکننده سند در جای دیگر)
- برابر `"-"` باشد یا با `"-"` و به دنبال آن هر کاراکتری آغاز شود
- برابر `"#"` باشد یا با `"#"` آغاز شود (خط به‌عنوان کامنت خوانده می‌شود)

در غیر این صورت، رشته‌ها می‌توانند بدون نقل‌قول باشند. یونیکد، ایموجی، و رشته‌های با فاصله‌های درونی (غیر پیشینی/پیانی) بدون نقل‌قول ایمن هستند:

```toon
message: Hello 世界 👋
note: This has inner spaces
```

### توالی‌های گریز (Escape Sequences)

در رشته‌ها و کلیدهای نقل‌قول‌شده، شش توالی گریز معتبر است:

| کاراکتر | گریز |
|-----------|--------|
| بک‌اسلش (`\`) | `\\` |
| نقل‌قول دوگانه (`"`) | `\"` |
| خط جدید (U+000A) | `\n` |
| بازگشت کارت (U+000D) | `\r` |
| تب (U+0009) | `\t` |
| هر کاراکتر کنترلی دیگر U+0000–U+001F | `\uXXXX` |

سایر گریزها (مثال: `\x`، `\0`، `\b`) همیشه رد می‌شوند، همانند مقادیر `\uXXXX` سرپا (U+D800–U+DFFF).

### تبدیل انواع

اعداد برای مقادیر در محدوده §2 در فرم دهدهی قانونمند صادر می‌شوند؛ نماد نمایی خارج از این محدوده مجاز است. انواع غیر-JSON (`NaN`، `Infinity`، `BigInt`، `Date`، `Set`، `Map`، `undefined` و غیره) قبل از کدگذاری نرمال‌سازی می‌شوند – برای نگاشت کامل به [مرجع API – نرمال‌سازی نوع](/reference/api#type-normalization) مراجعه کنید.

رمزگشاها هر دو فرم دهدهی و نمایی را در ورودی می‌پذیرند (مثال: `42`، `-3.14`، `1e-6`)، و توکن‌هایی با صفرهای پیشینی ممنوعه (مثال: `"05"`) را به‌عنوان رشته، نه عدد، می‌پذیرند.

### سریال‌سازی سفارشی با toJSON

اشیاء با متد `toJSON()` با فراخوانی متد و نرمال‌سازی نتایج آن قبل از کدگذاری سریال‌سازی می‌شوند، شبیه به `JSON.stringify`:

```ts
const obj = {
  data: 'example',
  toJSON() {
    return { info: this.data }
  }
}

encode(obj)
// info: example
```

متد `toJSON()`:

- بر نرمال‌سازی داخلی (Date، Array، Set، Map) اولویت دارد
- نتایج به‌صورت بازگشتی نرمال‌سازی می‌شوند
- برای اشیاء با `toJSON` در زنجیره پروتوتایپشان فراخوانی می‌شود
