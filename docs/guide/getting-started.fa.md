# شروع کار

## TOON چیست؟

**نمادگذاری شیءگرای توکن‌محور (Token-Oriented Object Notation)** یک کدگذاری فشرده و انسان‌خوانا از مدل دادهٔ JSON است که تعداد توکن‌ها را به حداقل می‌رساند و درک ساختار را برای مدل‌ها آسان می‌کند.

TOON ساختار مبتنی بر تورفتگی در YAML (برای اشیای تودرتو) را با قالب‌های جدولی به سبک CSV (برای داده‌های یکنواخت) ترکیب می‌کند. نقطهٔ قوت آن اشیای یکنواخت است؛ یعنی آیتم‌هایی که فیلدهای یکسان دارند، چه در یک آرایه باشند و چه با شناسه کلیدگذاری شده باشند. TOON در این حالت به فشردگی نزدیک به CSV می‌رسد و در عین حال ساختاری صریح اضافه می‌کند که به LLMها کمک می‌کند داده را قابل‌اعتمادتر تجزیه و اعتبارسنجی کنند. برای داده‌های عمیقاً تودرتو یا ناهمگون، ممکن است JSON کارآمدتر باشد.

آن را یک لایهٔ ترجمه در نظر بگیرید: در کد از JSON استفاده کنید و برای ورودی LLM آن را به TOON کدگذاری کنید. TOON نمایشی جایگزین‌پذیر و بدون اتلاف از همان JSON است که از قبل دارید.

### چرا TOON؟

توکن‌های LLM هزینه دارند و JSON استاندارد کلی است. یک پیش‌بینی آب‌وهوا در TOON:

```toon
location:
  city: Berlin
  country: DE
  units: metric
alerts[2]: frost,wind
forecast[3]{day,temp{min,max},condition,rainChance}:
  Mon,-2,4,snow,80
  Tue,1,7,cloudy,20
  Wed,3,11,sunny,5
```

همین داده در JSON حدود ۱۱۷ توکن است، در برابر حدود ۶۶ توکن در TOON:

```json
{
  "location": {
    "city": "Berlin",
    "country": "DE",
    "units": "metric"
  },
  "alerts": [
    "frost",
    "wind"
  ],
  "forecast": [
    {
      "day": "Mon",
      "temp": {
        "min": -2,
        "max": 4
      },
      "condition": "snow",
      "rainChance": 80
    },
    {
      "day": "Tue",
      "temp": {
        "min": 1,
        "max": 7
      },
      "condition": "cloudy",
      "rainChance": 20
    },
    {
      "day": "Wed",
      "temp": {
        "min": 3,
        "max": 11
      },
      "condition": "sunny",
      "rainChance": 5
    }
  ]
}
```

TOON برای شیء `location` از تورفتگی YAML، برای آرایهٔ ساده `alerts` از قالب درون‌خطی، و برای آرایهٔ `forecast` از قالب جدولی استفاده می‌کند: `[۳]` طول آرایه را اعلام می‌کند (به LLMها اجازه می‌دهد به پرسش‌های اندازه مجموعه‌داده پاسخ دهند و کوتاه‌سازی را تشخیص دهند)، `{day,…}` نام فیلدها را یک بار اعلام می‌کند، و هر ردیف مقادیر جدا شده با کاما را جریان می‌دهد. اشیای تودرتوی یکنواخت `temp` در سرایند به عنوان یک [گروه فیلد تودرتو](/guide/format-overview#nested-field-groups) (`temp{min,max}`) جمع می‌شوند در حالی که ردیف‌ها تخت (flat) باقی می‌مانند. هر قالب به‌طور خودکار بر اساس شکل داده انتخاب می‌شود.

الگو در کل TOON یکسان است: ساختار یک بار اعلام می‌شود، داده به‌صورت فشرده جریان می‌یابد – که باعث می‌شود به چگالی CSV برسد با حفظ ساختار صریح.

نقشه‌های اشیای یکنواخت نیز جمع می‌شوند: [قالب جدولی کلیددار](/guide/format-overview#keyed-tabular-objects) آن‌ها را به جدولی تبدیل می‌کند که ردیف‌های آن کلید خودشان را حمل می‌کنند.

### اهداف طراحی

TOON برای موارد خاص بهینه‌سازی شده و هدف دارد:

- آرایه‌های اشیای یکنواخت را تا حد امکان فشرده کند با اعلام یک‌باره ساختار و جریان داده.
- به‌طور کامل بدون اتلاف و قطعی باشد – رفت‌وبرگشت تمام داده و ساختار را حفظ می‌کند.
- تجزیه (parsing) را برای LLMها و انسان‌ها ساده و قوی نگه دارد از طریق نشانگرهای ساختاری صریح.
- نگه‌داری‌های اعتبارسنجی (طول آرایه، تعداد فیلد) فراهم کند که کمک می‌کنند کوتاه‌سازی و خروجی نادرست را تشخیص دهند.

## چه زمانی از TOON استفاده کنیم

TOON روی آرایه‌های اشیای یکنواخت – داده‌هایی با ساختار یکسان در سراسر آیتم‌ها – بهترین عملکرد را دارد. برای پرامپت‌های LLM، قالب متنی قطعی و بهینه‌شده تولید می‌کند که اعتبارسنجی داخلی دارد. طول آرایه‌های صریح (`[N]`) و لیست فیلدها (`{fields}`) به تشخیص کوتاه‌سازی و داده نادرست کمک می‌کنند، در حالی که قالب جدولی لیست فیلدها را یک بار اعلام می‌کند به‌جای تکرار در هر ردیف.

::: tip
قالب TOON پایدار است، اما هنوز ایده‌ای در حال تکامل است. هیچ چیز قطعی نیست. با مشارکت در [مشخصات (spec)](https://github.com/toon-format/spec) یا ارائهٔ بازخورد، در شکل‌دادن به مسیر آن سهیم شوید.
:::

## چه زمانی از TOON استفاده نکنیم

TOON همیشه بهترین انتخاب نیست. در موارد زیر گزینه‌های دیگر را در نظر بگیرید:

- **ساختارها عمیقاً تودرتو یا ناهمگون** (واجد شرایط بودن جدولی ≈ ۰٪): JSON فشرده اغلب توکن کمتری مصرف می‌کند. مثال: اشیاء پیکربندی پیچیده با سطوح تودرتو زیاد.
- **آرایه‌های نیمه‌یکنواخت** (~۴۰ تا ۶۰٪ واجد شرایط بودن جدولی): صرفه‌جویی توکن کاهش می‌یابد. اگر خط لوله‌های شما از قبل به JSON تکیه دارد، JSON را ترجیح دهید.
- **داده کاملاً جدولی**: CSV برای جداول تخت کوچک‌تر از TOON است. TOON سربار اندکی (~۵ تا ۱۰٪) می‌افزاید تا ساختار (اعلام طول آرایه، لیست فیلد، محدوده جداکننده) فراهم کند که اطمینان LLM را بهبود می‌بخشد.
- **برنامه‌های حساس به تأخیر**: روی تنظیمات دقیق خودتان بنچمارک بگیرید. برخی استقرارها (به‌ویژه مدل‌های محلی/کوانتیزه) ممکن است JSON فشرده را با وجود توکن بیشتر سریع‌تر پردازش کنند.

::: info
برای مقایسه‌های مبتنی بر داده در ساختارهای مختلف، به [بنچمارک‌ها](/guide/benchmarks) مراجعه کنید. هنگام بهینه‌سازی برای تأخیر، TTFT، توکن/ثانیه و زمان کل را برای هر دو TOON و JSON فشرده اندازه بگیرید، و در محیط خاص خودتان هر کدام سریع‌تر بود را استفاده کنید.
:::

## نصب

### کتابخانه TypeScript

کتابخانه را از طریق مدیر بسته دلخواه نصب کنید:

::: code-group

```bash [npm]
npm install @toon-format/toon
```

```bash [pnpm]
pnpm add @toon-format/toon
```

```bash [yarn]
yarn add @toon-format/toon
```

:::

### CLI

CLI را می‌توان بدون نصب از طریق `npx` استفاده کرد، یا به‌صورت سراسری نصب کرد:

::: code-group

```bash [npx (بدون نصب)]
npx @toon-format/cli input.json -o output.toon
```

```bash [npm]
npm install -g @toon-format/cli
```

```bash [pnpm]
pnpm add -g @toon-format/cli
```

```bash [yarn]
yarn global add @toon-format/cli
```

:::

برای مستندات کامل CLI، به [مرجع CLI](/cli/) مراجعه کنید.

## نوع رسانه و پسوند فایل

فایل‌های TOON به عرف از پسوند `.toon` استفاده می‌کنند. برای انتقال HTTP، نوع رسانه موقت `text/toon` است، همیشه با کدگذاری UTF-8. اگرچه می‌توانید `charset=utf-8` را صریحاً ذکر کنید، اما اختیاری است – UTF-8 پیش‌فرض فرض می‌شود. این فرآیند ثبت در [مشخصات §17](https://github.com/toon-format/spec/blob/main/SPEC.md#17-iana-considerations) تشریح شده است.

## اولین مثال شما

مثال‌های زیر از کتابخانه TypeScript برای نمایش استفاده می‌کنند، اما عملیات یکسان در هر زبانی با پیاده‌سازی TOON کار می‌کند.

بیایید یک مجموعه‌داده ساده را با کتابخانه TypeScript کدگذاری کنیم:

```ts
import { encode } from '@toon-format/toon'

const data = {
  users: [
    { id: 1, name: 'Ada', role: 'admin' },
    { id: 2, name: 'Bob', role: 'user' }
  ]
}

console.log(encode(data))
```

**خروجی:**

```toon
users[2]{id,name,role}:
  1,Ada,admin
  2,Bob,user
```

### رمزگشایی به JSON

رمزگشایی نیز همین‌قدر ساده است:

```ts
import { decode } from '@toon-format/toon'

const toon = `
users[2]{id,name,role}:
  1,Ada,admin
  2,Bob,user
`

const data = decode(toon)
console.log(JSON.stringify(data, null, 2))
```

**خروجی:**

```json
{
  "users": [
    { "id": 1, "name": "Ada", "role": "admin" },
    { "id": 2, "name": "Bob", "role": "user" }
  ]
}
```

رفت‌وبرگشت بدون اتلاف است: `decode(encode(x))` همیشه برابر `x` است (پس از نرمال‌سازی انواع غیر-JSON مانند `Date`، `NaN` و غیره).

## گام‌های بعدی

اکنون که اولین سند TOON خود را دیده‌ید، [نمای کلی قالب](/guide/format-overview) را برای جزئیات کامل نحو (اشیاء، آرایه‌ها، قالب‌های جدولی، قوانین نقل‌قول) بخوانید، سپس [استفاده از TOON با LLMها](/guide/llm-prompts) را برای دیدن نحوه استفاده موثر در پرامپت‌ها بررسی کنید. برای جزئیات پیاده‌سازی، [مرجع API](/reference/api) (TypeScript) یا [مشخصات](/reference/spec) (قوانین هنجاری भाषा-neutral) را ببینید.
